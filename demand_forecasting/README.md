# Demand Forecasting & Inventory Optimization

A four-week **Python + Jupyter Notebook** project aligned to the uploaded Data Science PDF's Project 1. It includes actual trained models, chronological evaluation, explicit inventory scenarios, a Python Streamlit dashboard and a Python FastAPI service.

**Bundled sales and model results are synthetic practice examples.** Import licensed historical sales for your real internship findings. No observed stock, supplier lead times or inventory savings are invented.

## Where are the models?

The complete ZIP and Week 3/4 ZIPs include genuine fitted pipelines generated by this project:

```text
models/demo/
├── linear_regression.joblib   # fitted preprocessing + Linear Regression
├── random_forest.joblib       # fitted preprocessing + Random Forest
├── selected_model.joblib      # validation-selected serving model
├── naive.json                # baseline rule and recent observations
├── seasonal_naive.json       # saved seven-day seasonal baseline
├── registry.json             # filenames, hashes, metrics and selected method
├── model_card.json           # source, versions and limitations
└── manifest.json             # splits, evaluation and provenance
```

Earlier releases generated only `outputs/demo/model.joblib` after training. This release supplies weights visibly in models/ and reuses a matching saved model when the dashboard restarts. New dashboard training persists to `models/runs/<dataset-id>/`, with reports under `reports/runs/<dataset-id>/`.

Python **3.12** is the tested target and meets the PDF's Python 3.9+ requirement. Application code and notebook kernels are Python. Libraries: pandas, NumPy, scikit-learn, statsmodels, SQL via SQLite, FastAPI, Streamlit/Plotly, matplotlib, joblib and pytest. JupyterLab/ipykernel run the notebooks. GitHub language percentages describe repository contents. They are not required percentages or Python versions and are not artificially adjusted. There is no custom JavaScript/TypeScript/HTML/CSS frontend or batch/shell implementation. See docs/PDF_REQUIREMENTS.md.

## Install once: Windows PowerShell

Extract the ZIP and open a terminal inside demand_forecasting:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

### Start or restart the dashboard

```powershell
.\.venv\Scripts\python.exe start_dashboard.py
```

Open the Local URL printed in the terminal. The bundled matching model loads automatically; no mandatory retraining is required on restart. Keep the terminal open; Ctrl+C stops it. The older app/streamlit_app.py command remains a compatible launcher.

### Learn through Jupyter

```powershell
.\.venv\Scripts\python.exe -m jupyterlab
```

Open notebooks/01_data_exploration.ipynb using the project environment's Python kernel. Read and Run All notebooks **01 → 02 → 03 → 04**, or work cell-by-cell. Each notebook has explanations, executable code, checks, tasks and learning resources.

### Rebuild all stages and test

```powershell
.\.venv\Scripts\python.exe run_week.py
.\.venv\Scripts\python.exe -m pytest -q
```

No PowerShell activation-policy change is needed. Subsequent restarts need only the dashboard command.

## Real data and separate training

Use [Store Item Demand Forecasting — Kaggle](https://www.kaggle.com/competitions/demand-forecasting-kernels-only/data). Review terms and download historical train.csv. Follow docs/DATA_GUIDE.md to select a small subset. Required columns: date,store,item,sales. IDs must be nonempty strings; sales finite/nonnegative; daily records continuous. Selected series must end on the same date. Full evaluation needs at least 98 days per series. Missing records are rejected, not replaced with invented zeros.

```bash
python -m src.cli prepare --input data/raw/retail_subset.csv --output reports/real_week01
python -m src.cli baseline --input data/raw/retail_subset.csv --output reports/real_week02
python -m src.cli train --input data/raw/retail_subset.csv --output reports/evaluation/retail --models models/retail
python -m src.cli forecast --input data/raw/retail_subset.csv --model models/retail/selected_model.joblib --output reports/evaluation/retail/future.csv
```

On PowerShell substitute `.\.venv\Scripts\python.exe` for python if not activated. In notebooks change DATA_PATH and use separate MODEL_DIR/REPORT_DIR paths. GUI uploads save new runs under models/runs/.

## Evaluation and limitations

Last 28 days: test. Preceding 28: validation. Earlier observations: training. Four seven-day origins per block use recursive predictions inside the horizon; actual history becomes available only between origins. Selection uses validation MAE only. Evaluation fits never train on test observations. Serving artifacts are refitted on all known history after evaluation; reported held-out scores describe the earlier fits, not independent validation of the serving refits.

Dashboard tabs: Sales overview, Forecasts, Inventory scenarios, Model performance, Models. Models lists actual files, selected method, provenance and a model download. Reports are under reports/evaluation/demo/; static examples under reports/reference/. Install pinned dependencies and load artifacts from trusted sources. Checksums detect changes, not publisher authenticity.

Inventory values are explicit hypothetical stock/lead-time/variability/service inputs. Safety stock uses an educational normal/independent-demand approximation. No calibrated stockout probability or guaranteed saving is claimed. A baseline is allowed to win.

## API and SQL

```bash
python -m uvicorn api.main:app --host 127.0.0.1 --port 8000
python -m src.cli sql
```

GET /models lists saved artifacts. POST /forecast supports selected, linear_regression, random_forest, naive and seasonal_naive. Set DEMAND_SALES_CSV and DEMAND_MODEL_PATH for your own compatible source/artifact. src.api:app is a compatibility alias. See docs/API.md. This unauthenticated educational API is intended for local use.

## Troubleshooting and upgrades

- Run from the project root so Python can import src and api.
- Use Python 3.12 and the pinned environment for supplied weights; retrain if you choose different compatible libraries.
- If a practice artifact is missing/corrupted, `python -m src.cli train` regenerates it. Use separate paths for real experiments.
- Investigate missing daily records and duplicate keys; do not silently invent zeros or aggregate uncertain duplicates.
- API/Jupyter/Streamlit checks need local sockets in managed sandboxes.
- Preserve .git, .venv, private raw data, local runs and your edits when upgrading. Compare cumulative ZIP changes before copying.
- requirements.txt lists direct tools; requirements-lock.txt records the tested environment, including Jupyter's transitive dependencies.
