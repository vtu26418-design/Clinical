# veltech-ams-mini 2.2.0 — upgrade and Android install

This release targets `https://app.veltech-mini-ams.me`. It includes the new mobile login and launch animation, combined campus logo, locally bundled Manrope font, one live Home reminder hub, separate mobile settings views, redesigned notifications and a real signed Android APK. The existing application, database and campus accounts are retained.

## Upgrade your existing AWS installation

1. Back up your database, media volume, `.env`, `.private` and server/proxy configuration. Keep the same database address, `CAMPUS_LINK_KEY`, `CAMPUS_SERVICE_KEY`, session keys and account records. Do not run a fresh setup over existing private files or replace them with example credentials.
2. Extract the full bundle. The `veltech-ams-mini` folder is the source project; the separate `android-release` folder is the already verified public Android release. Place the new source in your normal AWS release directory and retain the existing private configuration and persistent volumes.
3. Review [AWS-CLOUDFLARE-MOBILE.md](AWS-CLOUDFLARE-MOBILE.md). Set the real HTTPS origin in your existing configuration, keep secure cookies, use Cloudflare Full (strict), and trust only the actual reverse proxy address/subnet. Never cache private `/api/` responses. Do not disable WAF protections for the whole site.
4. Rebuild/start using your existing deployment's Compose files. For the standard PostgreSQL stack:

```bash
docker compose -f compose.production.yaml -f compose.postgres.production.yaml up -d --build
```

Use the files you already deploy; do not switch from an existing MongoDB/Atlas deployment to PostgreSQL as part of this UI update. The default Windows Docker setup uses:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\Start.ps1
```

On an existing configured installation use `Start.ps1`; preserve `.private` and your original database. No Ubuntu installation is required. See the earlier detailed V2-UPGRADE.md guide for storage, SMTP and normal deployment configuration.

## Publish the included Android release in the app

The full bundle's `android-release` folder contains only public release files: the checksum-named APK and `release.json`. It contains no signing key/password. It was generated by the publisher after independently checking the binary's signature, package, version and alignment. You can copy these files without installing the Android SDK on AWS.

In the existing `.private/campus.env` (or equivalent server configuration), use:

```dotenv
CAMPUS_APK_DIRECTORY=/app/media/app-releases
CAMPUS_ANDROID_PACKAGE_ID=in.velstudents.veltechams
CAMPUS_ORIGINS=https://app.veltech-mini-ams.me
CAMPUS_COOKIE_SECURE=true
```

`CAMPUS_APK_DIRECTORY` is a path inside the campus container, not your Windows host path. Using your usual Compose project/files, create the directory and copy the supplied public release folder into the persistent media volume:

```bash
docker compose exec -T campus mkdir -p /app/media/app-releases
docker compose cp ../android-release/. campus:/app/media/app-releases/
```

The example assumes you run the command from the extracted `veltech-ams-mini` directory. If your release folder is elsewhere, adjust only the source path. Ensure the running campus user can read the copied files. Restart/recreate the campus service with your normal deployment command after changing its environment. Every campus replica must read the same persistent release directory.

Open `/api/campus/app-release` on the deployed site; it should report `available: true`, version `2.2.0` and code `20200`. Metadata and APK downloads are intentionally public so a new student can install before signing in. Academic data and accounts remain authenticated. The installer checks the APK checksum before saving; a changed/stale release requires checking again.

In the app open Settings → Install & updates → Download Android APK. Open the saved `.apk` in Android Downloads and confirm the OS installation prompt. Android may ask permission to install from your browser. A website cannot silently install an APK. Web app installation is a separate secondary option, including Safari Add to Home Screen for iPhone. Android requires version7 or newer and a compatible browser.

## Verify Android domain association

The included web source/build contains `/.well-known/assetlinks.json` for this APK's signing certificate and package. It must be served at:

`https://app.veltech-mini-ams.me/.well-known/assetlinks.json`

Return HTTP200 JSON with no login, redirect or browser challenge. Cloudflare returned HTTP403/error1010 to this cloud's read-only checks. Follow the narrow exact-host/exact-path rule in the AWS guide so Android's verifier can read this one public file, keeping other protections enabled. Domain verification was not completed here. Until it succeeds the APK can open the site with browser controls. Test on an actual Android phone after deployment; no phone acceptance test was performed in this cloud.

Deploy the web update before distributing the APK: the APK uses your live HTTPS application, so it will otherwise display the previous hosted UI. The APK has the new local hybrid launcher icon even before the site is updated.

## Preserve the Android signing identity

This is a new release identity, package `in.velstudents.veltechams`, code `20200`. Public certificate fingerprints, APK checksum and signing receipt are included. Private signing files are deliberately absent from every public ZIP/repository. The workspace owner must privately retrieve and back up the generated keystore and password before this workspace expires. Private handover instructions are at `/workspace/.campus-mobile-v22/android-private/SIGNING-HANDOVER-PRIVATE.md` in this build workspace. Do not upload that directory, keystore or password to a public repository or send them through ordinary messages.

Future APK updates must use this exact key/package and a higher version code. Losing the key means the existing installation cannot accept your next signed update. Do not generate a replacement key as a password-recovery workaround. Follow ANDROID.md for Linux/Windows/CI builds and independent release verification.

## Student behavior and sync

- The Home top section combines current/next class, holidays, exams, the student's own seat and audience-matched staff publications. New announcements show for24hours; exam reminders return within72hours and become more urgent near the start. Unsupported source fields stay unavailable.
- Mobile settings opens each category as its own view. Password recovery and notice details use separate views. Notification read/delete actions keep the inbox visible and do not reload the whole workspace. Exam seating messages open Examinations directly.
- Duplicate same-owner GETs share a network request. Sync progress updates do not trigger a full academic snapshot unless record versions advance. Existing records remain visible while updating; offline/hidden work pauses and failures back off.
- Returning students retain their existing session and supported saved records. Read-only offline records expire after24hours; fresh sync, registration, publishing and payments require a connection. Offline logout still prevents automatic restoration.
