# Verified starter results · v3

These results were generated by the v3 backend on the frozen public 800-record starter cohort. They are actual fitted outputs, not UI placeholders. They demonstrate a reproducible retrospective workflow, not clinical validation or guaranteed improvements.

## Duration and prolonged-risk task

312 rows meet outcome eligibility. After chronological grouping and outcome-availability purging, the splits contain 105 training, 20 validation and 64 test records. The training-only prolonged threshold is 1,101 days. The test split has 6 prolonged outcomes; validation has zero. AUROC/AP are therefore undefined on validation. The recommendation uses validation Brier only; no test scores select models.

Validation recommendation: **text**, Brier **0.01773**. This selects a risk model, not necessarily the best duration estimator. On this small holdout the added tree branches do not beat the recommended text branch; additional model families are not a promise of better performance.

## Phase understanding task

291 single-phase records with exact start dates qualify; the splits contain 175/57/59 records. Explicit phase strings are redacted from text. Five canonical labels are supported, but this dataset has no Early Phase 1 examples and that class is not learned.

| Model | Test accuracy | Balanced accuracy | Macro F1 |
|---|---:|---:|---:|
| majority_baseline | 0.373 | 0.250 | 0.136 |
| phase_logistic | 0.559 | 0.482 | 0.475 |

The model disagrees with many registry labels. It is an educational consistency check; its uncalibrated scores cannot assign phases or replace protocol review. See full confusion matrices and support in the phase manifest.

## Files and reproduction

`examples/starter-duration/` and `examples/starter-phase/` include manifests, actual metrics, exclusions, held-out predictions, fitted local joblib artifacts and an example prediction. `server_run.json` records the verified API job. The archived source CSV/raw pages remain in `data/starter/`. The examples are not registered automatically in a new local GUI database.

Recommended: start the app, load the starter cohort in Data Manager, run Experiments, then train Phase Model. This generates trusted artifacts in your own store and enables predictions in the UI.

CLI alternative, from the project root using your virtual-environment Python:

```bash
python scripts/train_models.py --input data/starter/trials.csv --output results/starter-duration --config configs/research.json --metadata data/starter/metadata.json
python scripts/train_phase_model.py --input data/starter/trials.csv --output results/starter-phase --metadata data/starter/metadata.json
```

Use new output directories. These CLI runs do not add GUI history. Timestamps, IDs and source-metadata wrapper fields differ between CLI and API runs, so manifests are not byte-identical; compare source hashes, retained IDs, configuration and numerical outputs. Preserve versions in the included lock files.

## Interpretation limits

The completed-only convenience sample is not representative. Registry fields are latest-state and may contain post-start updates. Date precision excludes many older trials. There is no external cohort, prospective validation, causal claim or calibrated risk guarantee. Baseline-like feature names and temporal purging do not prove baseline provenance. Check bootstrap intervals and per-phase sample counts in the manifests. Never load joblib/pickle files from untrusted sources.
