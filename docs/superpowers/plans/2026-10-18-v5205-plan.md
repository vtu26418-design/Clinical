# Reliability, ML and Science Studio implementation plan

> **For agentic workers:** Use focused implementation and independent review. Parallel tasks have separate owned files; the controller integrates shared interfaces and verifies the final application.

**Goal:** Deliver working pretrained research inference, truthful Settings accuracy checks and editable scientific 3D explanations in the existing app.
**Architecture:** Preserve old model contracts, add opt-in feature/candidate paths with frozen lineage, use existing project authentication/PostgreSQL and strict declarative scene documents. Shared adapters connect Settings, Validation Lab and model report APIs.
**Tech stack:** Python3.12/FastAPI/scikit-learn/CatBoost/PostgreSQL16, React19/TypeScript/Three.js/R3F/Drei, Docker, browser speech.
**Spec:** docs/superpowers/specs/2026-10-18-v5205-design.md

## Global constraints

- No fabricated records, scores, dates, probabilities, enrollment or provenance; no test tuning.
- Preserve historical raw data/artifacts/predictions, PostgreSQL, roles and existing functionality.
- No required paid provider; no generated executable code; explicit user voice/provider action.
- Ship trained artifacts with honest retrospective research limitations; no perfect-accuracy claim.
- Windows Python3.12/Docker operation and a complete tested ZIP/guide are required.

## Review focus

- A late old-dataset response must never cancel or populate a new dataset's prediction.
- All consumed modalities/fields must match the selected task estimators, including constants and phase-only branches.
- Stored historical predictions must not acquire fresh active-model provenance.
- Empty/partial/one-class or unlabeled evaluation cannot become an accuracy percentage.
- Malformed/oversized/provider-generated storyboards cannot execute scripts or access another project.
