# Clinical Trial Intelligence v5.2.0.2 design

The user authorizes implementing the complete upgrade now, with a ZIP and an end-to-end guide PDF. Preserve existing research workflows and authentic source data. Improve the application rather than add a marketing page. No fabricated clinical measurements, attribution values, uncertainty, or model-learning claims.

## Product and visual design

Use an uncluttered navy (#10283f), teal (#087f8c), white (#ffffff), and cool gray (#f4f7fa) visual system. Typography uses a local/system sans-serif stack, readable chart labels, and explicit control sizing. Rounded corners are restrained (10–14px). A grouped left navigation, compact workspace header, keyboard-accessible controls, and a distinct project launcher after login organize the existing application. Keep UI copy short; methodology and detailed instructions belong in disclosure panels and the guide.

## Database and access

PostgreSQL is required in every application mode, including development and tests. No SQLite fallback or SQLite database files. Store identity, sessions, projects, roles, invitations, audit, feedback, chat, and dataset/experiment metadata in PostgreSQL. Dataset source files and frozen model artifacts remain on persistent disk. Docker Compose includes PostgreSQL health checks and persistent volumes; initialization generates local credentials into an ignored .env. Production retains HTTPS cookie/origin protections and PostgreSQL TLS requirements.

Roles are owner, researcher (display: Trial researcher), reviewer (display: Clinical reviewer), and viewer. Owner manages members/settings, trains/approves/activates models, and has all research capabilities. Researcher imports/edits research, predicts, runs scenarios, and uses assistant. Reviewer reads/predicts, reviews evidence, and uses assistant if enabled. Viewer reads/predicts/explains/exports but cannot mutate, train, or use paid assistant. Enforce capabilities on the server, reflect them in navigation, and protect final-owner membership. Rate limiting wraps research forwarding and trusts only configured proxy origins. Feedback validates actual message membership; no client identifiers become filenames.

## Evidence APIs

Keep existing project-scoped research workspace, prediction and scenario APIs. Repair /api/v1/whatif to preserve the selected baseline, apply supported overrides only, return actual saved-model output/provenance or unavailable, and separate user-defined planning assumptions. Repair /api/v1/explain to return genuine saved-model duration_explanation; constant baselines have zero feature effects, unsupported local explanations remain unavailable. No demonstration fallback. Add real full-cohort graph aggregation to POST /api/v1/overview/graphs and expose graph metadata via GET /api/v1/graph-types. Include source dataset ID, row count, missingness and denominators. Recruitment endpoints use supported recruitment/site columns only; absent stages are unknown. Pipeline status derives from experiment lifecycle, not fabricated percentages. An optional richer GET /api/v1/visualizations/study?dataset_id=&nct_id= response may expose the workspace plus data availability for animations. Share its contract before frontend integration.

## Overview and seven animations

Selectable and persisted overview graphs: phase counts, status counts, enrollment distribution, PCI distribution, enrollment versus PCI, observed duration by phase, enrollment by phase, PCI component summary, date timeline, missingness, start-year activity, and model comparison when evidence exists. Aggregate the full dataset, not the first page. Allow phase/status filtering, graph selection/reordering, fullscreen, CSV/JSON export, and clear empty states.

All seven animations are implemented as functional, accessible components: (1) protocol → processing → model → prediction pipeline with real request/job states; (2) observed trial dates and phase education, separating predicted overall completion from unmodelled stage durations; (3) signed actual attribution or accurately labelled global importance/fusion contributions; (4) recruitment stages and sites if data exists, unknown states otherwise; (5) actual model-backed scenario changes plus explicitly labelled planning arithmetic; (6) structured metadata and protocol text flowing through the model's actual encoder/fusion branches; (7) pointer-responsive decorative DNA helix on the research home, with pause and reduced-motion support. Prediction Studio shows the animated journey after prediction. No EHR/genomic/imaging prediction claims.

## Assistant

Use readable Markdown, streaming responses, source references, clear errors, conversation history, provider/profile selection, copy/export and feedback controls. Improve grounding with actual selected-study, cohort, model, protocol and saved evidence context. Make response/context budgets configurable, with owner-controlled project limits; 0 can mean no daily application quota while rate limits remain. Feedback is project-scoped and can supply reviewed corrections to future prompts; no automatic weight changes. Retraining creates a candidate that requires held-out evaluation and owner approval. No guarantee of universally correct answers or unlimited provider context.

## Model improvements

Preserve verified bundled artifacts as baselines. Improve prediction provenance, explanation integrity, calibration/interval display and scenario validity. Add at least one reproducible model-training comparison improvement only if it can be evaluated with retained temporal splits; never relabel old metrics as new. Existing optional survival and BioBERT capabilities remain accurately documented. The 800-record frozen cohort limits generalization, and the approved median baseline must not be replaced unless validation supports it.
