# v5.2.0 release design

The user requests an upgraded research workbench, a distributable ZIP, a project preview, and a complete guide. The checked-out v5 is the base; the uploaded v5.1 archive is unavailable because it exceeds the transfer tool's 32 MiB limit. Four supplied PDFs and the prompt are design inputs, not evidence that their features or compliance claims already exist.

## Architecture and intended behavior
Retain Python 3.12, FastAPI, the project-scoped SQLite/PostgreSQL store, existing session cookies, four project roles, approved duration/phase artifacts, React/Vite, and existing research screens. Add a v5.2 extension router with fixed-host research connectors (ClinicalTrials.gov, PubMed, openFDA), normalized cited evidence, server-persisted project bookmarks, and configured email verification with expiring hashed single-use tokens. Keep provider keys on the server. Add a research-home screen, evidence search/saved library, account verification screen, a polished responsive workspace theme, model pipeline/fusion animation, and a decorative molecular graphic. Preserve the existing real scenario calculations and model provenance.

Use explicit source labels, timestamps and source links for research results. Read-only users may search/read; only owner/researcher may mutate project research bookmarks. Email verification is opt-in for existing local installations and required when the operator enables it; confirmation must not create a session. No actual email is sent during tests. Use configured HTTPS transactional email with mocked delivery tests and no embedded credentials.

Preserve the existing approved models. Add reproducible cohort-monitoring and training guidance with temporal leakage checks and explicit candidate review/promotion. Do not claim that trial completion equals success, that hundreds of thousands of records were trained here, that a model is mistake-free, or that adding software features establishes HIPAA/Part 11 compliance. Large-cohort collection, prospective validation, OAuth/SSO and production deployment depend on external infrastructure/data and remain explicit requirements. Provider model names are configurable; availability requires the operator's account.

## Visual system
A calm research workspace with deep navy navigation, pale blue-gray canvas, white content surfaces, teal accents and dark legible typography. A clear home workflow leads to import, prediction, evidence, scenario and reporting. Use native accessible controls, reduced-motion support and truthful empty states. Visual preview is a downloadable self-contained software-fixture build, not a deployed backend.

## Acceptance
The baseline suite remains green; meaningful tests cover research adapters, source failures, project isolation, role enforcement, token expiry/single use and credential-free delivery behavior. Production frontend typecheck/build passes. Run browser workflows at desktop/mobile, live local startup/health/bootstrap, approved-model replay, and packaged checksum verification. ZIP excludes secrets, runtime databases, dependencies and old ZIPs, includes built UI, preview, source and full documentation. Report optional integrations that were not exercised.
